ON-SCREEN PANEL  (F6 > HUD)
---------------------------
  [ok]   Hide the game's HUD (2026-10-22): F11 or F6 > HUD, saved as
         hide_game_hud. In a mission the GPU plugin skips every draw after
         the game's final screen pass (822F99ECDB1B0ACD) until the frame is
         shown, so subtitles, banners and the pause menu are hidden too while
         it is on; title and hub menus are unaffected. SDK patch 8. (Skipping
         the HUD's own task, CCockpit sub_82394AF0, only froze it: the
         sprites are drawn elsewhere.)
  [ok]   Frame rate (relabelled 2026-10-22): "FPS" is the game's real
         frame rate (30, as on the Xbox 360; 60 with the 60 fps option).
         "Window redraws" is how often the window is repainted (follows
         the monitor and repeats the same game frame), so a 144 Hz monitor
         does not mean the game is failing to reach 144.
  [test] Health, enemies (alive / nearest / last hit), speedrun timer,
         position.
  [ok]   Any corner of the screen.


VIDEO  (F6 > Shader, launcher)
------------------------------
  [ok]   Render scale 1x - 7x (the game always draws 1280x720; scale is
         the real internal resolution, e.g. 3x = 3840x2160).
  [test] Renderer (2026-10-22): Direct3D 12 (default) or Vulkan (work in
         progress), in the launcher or F6 > Game > Renderer (restart to
         switch); gpu_backend in tenchuz.toml. If Vulkan cannot start (no driver, old GPU) the
         game falls back to Direct3D 12 and says so in F6 > Game. Vulkan
         follows "Allow tearing" (no tearing by default). Shader presets
         need Direct3D 12. Checked on NVIDIA (menus and mission 51); other
         GPUs untested.
  [test] Fixed: with Vulkan, characters were noisy pixels on NVIDIA (the
         alpha test ignored use_fuzzy_alpha_epsilon), and roofs, wooden
         beams, carts and trees were missing or see-through (textures with
         a LOD bias were scaled to near black). SDK patch 6. Checked in
         mission 51 against Direct3D 12.
  [test] Black menu fix (2026-10-23): F6 > Game > "Sync GPU-written memory
         every frame" (clear_memory_page_state in tenchuz.toml, applies at
         once). On by default; off is Xenia's
         d3d12_clear_memory_page_state = false, which a player reports
         fixes menus showing black. Not yet tried on a PC with black menus.
  [test] Performance settings (2026-10-23): readback_memexport = false and
         occlusion_query_enable = false in the shipped tenchuz.toml, the
         choices Xenia players use for this game (no CPU wait on GPU memory
         writes; visibility queries answered "visible" instead of measured).
         A/B in a mission (RTX 4060 Ti, Direct3D 12): no visible difference
         either way, nothing broke, so they stay for slower PCs. Vulkan ran
         at about the same frame rate with them. Set either back to true if
         something looks wrong.
  [exp]  60 fps (2026-10-22): F6 > Game > 60 fps (experimental), or the
         launcher's "60 fps while playing"; frame_rate_60 in tenchuz.toml,
         applies at once. The game normally shows a new frame every second
         vertical blank (30 fps); while your character is in the world it
         now shows one every blank. Menus stay at 30 (they ran too fast at
         60). Game speed stays normal because the clock is still the 60 Hz
         refresh. Measured 55-60 fps in missions on Direct3D 12, about 54 on
         Vulkan. Not yet checked: cutscenes, the pause menu.
  [bug]  Vulkan, NVIDIA (2026-10-22): the wooden walkway under the eaves
         in mission 1 is speckled red/green or flat purple (floor shader
         ACFA07437578EA9C). Direct3D 12, the default, draws it correctly.
         All its inputs (textures, vertex data, constants, texture slots)
         were checked and are correct; the wrong result changes when
         unrelated code is added to the shader, so it looks like undefined
         behaviour in the NVIDIA Vulkan shader compiler. Direct3D 12's
         bindful mode showed the same purple. Parked.
  [test] Vulkan: the Xbox 360 rule "0 or a denormal times anything is 0"
         now also treats denormals as zero on GPUs that keep them (NVIDIA
         on Vulkan cannot flush them). SDK patch 9. Did not fix the floor.
  [test] Background speed (2026-10-22): the game runs at above-normal
         priority so it keeps its frame rate in missions while its window
         is in the background (Windows boosts only the window in front).
  [gone] F6 > Video tab removed (2026-10-21): its live overrides of the
         game's own post-processing (exposure, bloom, HDR, blur, tone
         mapping, depth of field) are replaced by the shader presets. The
         frame size readout went with it; render scale is in the launcher.
         Old fx_* keys were removed from tenchuz.toml.
  [ok]   ReShade works (Direct3D 12; colour effects only, see docs).
  [ok]   Custom pixel shaders: put <HASH>.ps.hlsl in shader_overrides\ or
         mods\<Mod>\shaders\ and it replaces that game shader (compiled at
         startup; errors fall back to the original). shader_overrides\
         wins over mods. Off switch: shader_overrides_enabled in
         tenchuz.toml. Guide: docs\shader_modding.md.
  [ok]   Shader presets: each subfolder of shader_overrides\ (or a mod's
         shaders\) is a preset. F6 > Shader > Preset picks one, or Original;
         switching needs a restart (Restart now button). Saved as
         shader_preset in tenchuz.toml.
  [ok]   "Modern Look" preset (extras\shader_overrides\Modern Look):
         replaces the final screen pass (822F99ECDB1B0ACD) and adds
         sharpening, clarity, bloom, a highlight roll-off, colour grading,
         vignette and dithering on top of the game's own blur/DOF/bloom.
  [ok]   "Manga" preset (extras\shader_overrides\Manga): ink outlines,
         flat tone bands, halftone screentone and paper colour; the Colour
         slider turns it into a colour comic.
  [ok]   Manga ink lines drawn on the dark side of edges only (half as
         thick) and sized in whole screen pixels (no pixelation when thin).
  [ok]   F6 > Shader: live sliders for the active preset (from its
         preset.ini), an effects on/off switch and a split-screen compare.
         Values saved per preset in shader_settings.ini. Shader files read
         them as XeUser(0..47).
  [ok]   The game passes the camera (eye, direction, field of view) and a
         clock to every shader (XeUser(48..61)), so shaders can rebuild
         world positions. Verified with a world grid on the hub puddle.
  [gone] Modern Look puddle water (79481E88F9E67594) removed 2026-10-22: it
         only affected puddles, so puddles are back to the game's own
         shader and its 7 sliders are gone. The depth effect sliders moved
         from XeUser(22..30) to XeUser(15..23).
  [ok]   Modern Look depth effects: ambient occlusion, atmospheric haze
         with tint, depth of field focused on the player, and light shafts
         from bright distant areas (they always come from above the screen;
         the moon's real position is not known). 9 sliders. The game's depth
         texture holds about k / distance; k is measured every frame at the
         player (the game passes the player's screen position and distance,
         XeUser(40..43)). Fixed 2026-10-21: haze only reached ~10 ft and
         DOF/shafts did nothing, because depth was read as plain distance.
  [todo] Water effects (rivers and puddles): left as the game draws
         them. River water's shader is not identified yet (probably drawn
         additively); an in-game shader picker would be the next step.
  [ok]   Fixed: with shader overrides active, some textures came out as a
         flat colour (mission 1: purple wooden walkway, magenta HUD orb).
         Cause: overrides switched the renderer to its bindful resource
         mode. They now work in the default bindless mode, so the renderer
         is left alone.


ONLINE  (F6 > Online, game's System Link mode)
----------------------------------------------
  [ok]   System Link multiplayer over IP: host and join with the game's own
         System Link menu. Verified with two copies on one PC (both players
         in the village). Not yet tested between two PCs or over the
         internet. Guide: docs\multiplayer.md.
  [test] Join by IP (net_join_ip, set by Join in F6 > Online): search asks
         that host directly, so play works over virtual LANs (ZeroTier,
         Radmin, Tailscale) or port forwarding. The join box takes codes or
         plain addresses.
  [test] F6 > Online > Advanced: This PC's address (net_bind_ip) for
         virtual LANs, this PC's local addresses with Copy buttons, and the
         router (UPnP) on/off switch.
  [ok]   Join codes, the simple way (2026-10-21): F6 > Online > Host a game
         > "Get my join code" opens the game's ports on the router (UPnP,
         remembered as net_upnp; again at every start, closed at exit) and
         shows the code (e.g. K3F9-2QX7) with a Copy button. Friends paste it
         under Join a friend (Paste button or Ctrl+V) and press Join, then
         Search in System Link. Verified with two copies on one PC (code
         copied and pasted, search found the host, join worked). Not yet
         tested between two networks.
  [ok]   Router port opening verified with a real router (opened, internet
         address read, closed again on exit).
  [test] If the router refuses, the internet address comes from a public
         STUN server (Google, else Cloudflare) and the code is still shown,
         with a note to forward the ports by hand or use a virtual LAN.
  [test] With a virtual LAN address set (Advanced > This PC's address), the
         join code stands for that address. The two-copy test script uses this
         (each copy shows a code for 127.0.0.x).
  [test] Each PC tells the other players its internet address
         (net_public_ip, in its System Link address), so players on other
         networks reach it across the internet.
  [ok]   Fixed: the host answered System Link searches only with a
         broadcast, so players joining by code never saw the game. It now
         also answers searchers from other networks directly.
  [ok]   Fixed: a host with a join address left from an earlier game sent
         its search answers there (or to itself) instead of to the player
         searching. Hosts now always answer the searcher.
  [test] Recent table in F6 > Online: the last 5 codes joined, with date,
         and Join / Copy / Remove buttons (net_recent_hosts).
  [test] Fixed: Ctrl+V / Ctrl+C / Ctrl+A did nothing in menu text fields
         (the runtime never passed Ctrl to the menus correctly).
  [ok]   Player name (F6 > Online > Your name, user_name): what other
         players see instead of "User". Applies after a restart (Restart
         now button). Verified with two copies (Rikimaru and Ayame shown in
         the joined game). Fixed 2026-10-21: any other name crashed the game,
         because the runtime kept profile files in a folder named after the
         player, and a new name meant an empty folder. It now always uses
         the "User" profile folder, so saves and settings stay put.
  [ok]   Fixed 2026-10-22: the partner card at the top left (colored P1-P4
         badge frame, health bar, name) showed as striped boxes. Cause: a
         recompiler bug in the vector pack instructions vpkuwus / vpkuhus
         when the result register is also an input (vpkuwus v0,v0,v0): the
         game builds the card's sprite sizes that way at startup, and they
         came out as 65535. Fixed in the recompiler (SDK patch 4); every
         place the game uses these instructions was regenerated. Verified
         in a co-op mission: the card matches the Xbox.
         (The flashing light specks in the air are dust; the Xbox has them
         too.)
  [ok]   tools\systemlink_test.ps1 runs two copies on one PC for testing
         (join with the codes; -PresetJoin skips them). Runs both at 1x
         render scale by default: at 3x the two copies fight over the GPU,
         the one you are not playing in drops to a few frames a second and
         enemies stutter on the other screen (verified: smooth at 1x).
  [test] The game keeps full speed when its window is in the background
         (1 ms timer, Windows background throttling off), so a host who
         alt-tabs does not slow down the game for the other players.
  [ok]   Single-player levels in multiplayer (2026-10-23): F6 > Online,
         pick one of the 14 single-player missions and tick "Use this level
         in multiplayer" in the System Link lobby (host). A background search
         finds the lobby's level setting (layout and level ids from a
         community Xenia cheat table) and keeps the chosen level written
         there. Verified hosting System Link: Daylight Battle On Deck, then
         Divine Punishment Tenchu, loaded as chosen.

SETTINGS
--------
  All settings live in tenchuz.toml next to tenchuz.exe. The launcher and
  the F6 menu both edit it in place (comments and [log.levels] kept).
  Do not use the runtime's own F4 settings screen "Save to config" button:
  it rewrites the whole file and drops those.
